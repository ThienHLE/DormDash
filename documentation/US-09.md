# US-09: Estimated Delivery Time

US-09 asks for an estimate tied to the active delivery that updates as its status or courier location changes. The current API provides walking duration through the map endpoint, but does not implement a separate live ETA endpoint.

### POST `/api/v1/maps/delivery` (shared with US-14)

Source: [`maps.js`](../api/endpoints/maps.js). See [US-13/US-14](US-13,US-14.md) for the full request, response, authorization, and error documentation.

**Access:** Logged-in requester or assigned courier. **Body:** `{ "deliveryId": "DELIVERY_OBJECT_ID" }`.

The backend resolves the delivery's pickup and drop-off location names and requests an OpenRouteService walking route. On HTTP 200, the JSON response includes:

```js
content: {
  deliveryId,
  status,
  pickup,
  dropoff,
  route: {
    geometry,
    distanceMeters,
    durationSeconds,
    attribution
  }
}
```

`durationSeconds` is the estimated walking duration for **pickup to drop-off**. A frontend can display approximate minutes using `Math.ceil(durationSeconds / 60)`. It is associated with the requested delivery through `content.deliveryId`.

## Current Limitations

- The endpoint does not read the courier's tracking document or change the route based on pickup status.
- It calculates the same pickup-to-drop-off journey even if the courier is elsewhere.
- Each call requests a fresh route, but status/GPS changes do not automatically trigger recalculation.
- It returns no `estimatedArrivalAt` timestamp and includes no pickup waiting or handoff allowance.
- There is no active-status restriction on the map endpoint.

Therefore, the current response supports a route walking-time estimate, but **does not fully satisfy the live ETA acceptance criteria**. Polling the tracking endpoint alone will not update this route duration.
