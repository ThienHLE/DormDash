# US-13 and US-14: Tracking, Locations, and Maps

This document covers the current endpoints in `tracking.js`, `locations.js`, and `maps.js`.

All endpoints below use **POST**, accept JSON where a body is required, and require a logged-in session. The frontend must send the session cookie. Responses use the matching HTTP status and this JSON format:

```json
{
  "statusCode": 200,
  "statusMessage": "Description of the result.",
  "content": {}
}
```

Errors normally have an empty `content` object. MongoDB ObjectIds are returned as strings and dates as ISO strings. `deliveryId` means the delivery document's `_id`, not a location ID.

## US-13: Live Courier Location

Source: [`tracking.js`](../api/endpoints/tracking.js).

Tracking uses **HTTP polling**, not Socket.IO. The courier's browser obtains GPS coordinates and sends updates; the requester's browser periodically retrieves the latest saved position. These endpoints do not run their own timers or obtain GPS directly.

Both endpoints require the delivery to be `accepted` or `picked_up`, with no `confirmationCodes` record marked `confirmed: true` for that delivery.

### POST `/api/v1/tracking/update`

**Access:** Only the courier assigned to the delivery.

**Body:**

```js
{
  deliveryId: "DELIVERY_OBJECT_ID",
  latitude: position.coords.latitude,
  longitude: position.coords.longitude,
  accuracy: position.coords.accuracy,
  capturedAt: position.timestamp
}
```

Latitude must be between -90 and 90, longitude between -180 and 180, and accuracy a non-negative number in meters. `capturedAt` is a numeric Unix timestamp in milliseconds: no more than 30 seconds old or 5 seconds in the future, relative to the server.

The backend identifies the courier from their session and upserts a document in `tracking`. Its `_id` is the delivery ID, so there is one latest-position record per delivery, not a location history. The record contains `userId`, coordinates, accuracy, `capturedAt`, and server-generated `updatedAt`. Older or equal capture timestamps do not overwrite the stored position.

**Success — 200:**

```json
{
  "statusCode": 200,
  "statusMessage": "Location update processed.",
  "content": { "deliveryId": "DELIVERY_OBJECT_ID" }
}
```

The same success response is used when an older update is ignored.

### POST `/api/v1/tracking/location`

**Access:** Only the delivery's requester.

**Body:** `{ "deliveryId": "DELIVERY_OBJECT_ID" }`

Retrieves the latest position matching both the delivery and its currently assigned courier. It checks delivery activity before returning coordinates.

**Success — 200, `content`:**

```js
{
  deliveryId: "DELIVERY_OBJECT_ID",
  trackingStatus: "live",
  location: {
    latitude: 35.0,
    longitude: -94.0,
    accuracy: 20,
    capturedAt: "2026-10-18T12:00:00.000Z",
    updatedAt: "2026-10-18T12:00:01.000Z"
  }
}
```

Coordinates and dates above are illustrative.

| Tracking status | Meaning |
| --- | --- |
| `waiting` | No matching position exists. `location` is `null`; message is `Waiting for the courier location.` |
| `live` | The saved capture timestamp is no more than 15 seconds old. |
| `stale` | The capture timestamp is older than 15 seconds or unusable. The last-known location is still returned. |

For `live` and `stale`, the message is `Courier location retrieved.` Page closure is not detected directly: the frontend must stop its GPS watcher and requests, after which the saved position becomes stale. The backend does not delete that position on page close.

### Tracking errors

| HTTP status | Meaning |
| --- | --- |
| 400 | Invalid delivery ID, coordinates, accuracy, or capture timestamp. |
| 401 | No login session. |
| 403 | Caller is not the assigned courier for updates, or not the requester for reads. |
| 404 | Delivery not found. |
| 409 | Delivery is not active or has been confirmed; no coordinates are returned. |
| 500 | Unexpected processing/database failure. |

## US-14: Campus Locations and Walking Routes

Sources: [`locations.js`](../api/endpoints/locations.js) and [`maps.js`](../api/endpoints/maps.js).

Admins create named campus markers in the `locations` collection. Request forms use those names for pickup/drop-off choices. Deliveries store `pickupLocation` and `deliveryLocation` as **names**, and the map endpoint resolves those names to coordinates. Names must match exactly.

### POST `/api/v1/locations/list`

**Access:** Any signed-in user. **Body:** None required.

Returns locations with `active: true`, sorted by name. Used by map markers, request dropdowns, and building filters.

**Success — 200:** Message `Locations retrieved.`, with `content: { locations: [...] }`. Each document contains `_id`, `name`, `latitude`, `longitude`, `active`, `createdAt`, and `updatedAt`. An empty collection returns `locations: []`.

### POST `/api/v1/locations/create`

**Access:** Admin; the role is checked against the current `users` record.

**Body example (illustrative coordinates):**

```json
{
  "name": "Library Entrance",
  "latitude": 35.0,
  "longitude": -94.0
}
```

Trims the name and validates a length of 1–100 characters and numeric coordinate ranges. Creates a document with `active: true` and creation/update timestamps. A unique database index on `name` prevents duplicate exact names, including names of inactive locations. There is no location-editing endpoint.

**Success — 201:** Message `Location created.`, with `content: { location: {...} }` containing the saved document and its `_id`.

### POST `/api/v1/locations/:id/deactivate`

**Access:** Admin. **Body:** None required. `:id` is the location's 24-character ObjectId string.

Sets `active: false` and refreshes `updatedAt`. This hides the location from the active list without deleting it, so existing delivery maps can still resolve it.

**Success — 200:** Message `Location deactivated.`, with `content: { location: {...} }` containing the updated document.

### Location errors

| HTTP status | Meaning |
| --- | --- |
| 400 | Invalid name, coordinates, or location ID. |
| 401 | No login session. |
| 403 | Admin access required for creation/deactivation. |
| 404 | Location to deactivate was not found. |
| 409 | Duplicate name, or existing duplicates prevent creating the unique index. |
| 500 | Unexpected processing/database failure. |

### POST `/api/v1/maps/delivery`

**Access:** The delivery's requester or assigned courier.

**Body:** `{ "deliveryId": "DELIVERY_OBJECT_ID" }`

The endpoint loads the delivery, checks access, and resolves its pickup/drop-off names in `locations`. Deactivated locations are allowed for existing deliveries. After validating coordinates, it calls OpenRouteService's `foot-walking/geojson` directions endpoint using the backend's `ORS_API_KEY`, with a 10-second timeout.

**Success — 200:** Message `Delivery map and walking route retrieved.`, with:

```js
content: {
  deliveryId: "DELIVERY_OBJECT_ID",
  status: "accepted",
  pickup: { _id, name, latitude, longitude },
  dropoff: { _id, name, latitude, longitude },
  route: {
    geometry,          // GeoJSON LineString
    distanceMeters,
    durationSeconds,
    attribution        // Included when supplied by OpenRouteService
  }
}
```

The frontend draws markers and the GeoJSON route in Leaflet. GeoJSON coordinates use **[longitude, latitude]**; Leaflet marker arrays use **[latitude, longitude]**.

This is a **pickup-to-drop-off walking route**, not a route from the courier's live GPS position. Duration is the route's walking-time estimate, not a live arrival prediction. Every call requests a route; this endpoint does not cache results. A routing failure returns an error rather than a partial marker response. It does not require an active delivery status, unlike tracking.

| HTTP status | Meaning |
| --- | --- |
| 400 | Invalid delivery ID. |
| 401 | No login session. |
| 403 | Caller is not the requester or assigned courier. |
| 404 | Delivery not found. |
| 409 | Missing/unmatched location names or invalid saved coordinates. |
| 500 | Unexpected processing/database failure. |
| 502 | Routing request failed or returned invalid route data. |
| 503 | `ORS_API_KEY` is not configured. |
| 504 | Routing request timed out. |
